## 2. 信息架构（v0.2：创作 + 运营）

Easel 负责**做内容**，[CreatorHub](https://github.com/3441293738/creatorhub) 的思路负责**管账号**。两者合起来，覆盖"找灵感 → 做内容 → 发出去 → 看反馈 → 回复互动"的完整闭环。

### 导航

```
┌──────────────────────┐
│ 🟧 自媒搭子            │
│ 正在为「小林的生活记录」▾│  ← 当前账号人设
│                      │
│ ⌂  今天               │  待处理 + 今日选题 + 进行中 + 本周发布
│                      │
│ 创作                  │
│ ✦  找灵感             │  热点 / 选题库 / 拆解爆款 / 对标账号
│ ✎  AI 创作            │  对话 + 作品实时预览 + 模板 + 全部能力
│ ▦  作品库             │  生成的作品，按平台和状态筛选
│                      │
│ 运营                  │
│ ➚  发布               │  发布中心 / 内容日历 / 发布记录
│ 💬 互动          ●5   │  评论 / 私信，AI 起草回复
│ 📈 数据               │  粉丝与作品表现、复盘建议
│                      │
│ ─────────────────    │
│ 👤 账号与定位          │  平台账号登录 + 账号人设
│ [会员卡：23 天 · 68%]  │
│ ⚙  设置               │  通知 / 外观 / 存储 / 关于
└──────────────────────┘
```

- **首页改名「今天」**，最上面是"待处理"，比如 5 条新评论、1 条私信、1 个发布失败。这一块借鉴 CreatorHub 的"工作概览"，让用户每天打开就知道先做什么
- 其余调整同 v0.1：去掉"通用模式"、网关状态和模型配置；首次使用走 3 步问答

### CreatorHub 功能对照

CreatorHub **没有开源许可证**，代码不能用于商业产品。以下功能都参考它的设计、由我们自己实现，底层尽量复用 Easel 已有的登录态和脚本（`account_stats.py`、`social_stats.py`、`xhs_comment.py`、各平台发布脚本、`publish_queue.py`）。

| CreatorHub | 自媒搭子里的位置 | 做法 |
|---|---|---|
| 工作概览 | 今天 · 待处理 | 汇总新评论、私信、失败任务 |
| 平台账号 | 账号与定位 | 复用 Easel 的 7 平台登录，不另建一套 |
| 我的内容：作品 / 粉丝 / 关注 | 数据 | 定时低频同步（30–60 分钟一次） |
| 评论监控（自己的作品） | 互动 · 评论 | 新评论提醒 + **AI 按账号人设起草回复，用户确认后发送** |
| 我的内容：私信 | 互动 · 私信 | 只读同步 + 新消息提醒；回复时打开平台页面（放在最后做，技术风险最高） |
| 作品监控（他人主页） | 找灵感 · 对标账号 | 只看对标账号公开作品的标题和数据，低频；直接接入「拆解爆款」 |
| 任务队列 | 发布 · 发布记录 + 今天 · 待处理 | 生成中、待发布、失败，统一在这里看 |
| 发布 / 转发 | 发布 | Easel 已支持 7 个平台 |
| 自动评论 | 改成「AI 起草，人工确认」 | 只回复**自己作品下**的评论，不自动去别人作品下评论 |
| 链接下载 | 并入「拆解爆款」 | 贴链接做分析；不做批量下载他人作品 |
| 通知 | 设置 · 通知 | Easel 已有飞书 / 钉钉 / 企业微信推送 |
| 风控中心 | 不做独立页面 | 内置保守的频率上限；需要登录或平台弹出安全验证时提醒用户 |
| 关键词批量采集（含评论） | **不做** | 见下 |
| 指纹浏览器内核、代理池、风控规避 | **不做** | 见下 |
| 自动私信、自动关注 | **不做** | 见下 |
| 弹幕监控 | 暂不做 | 使用价值低 |

**不做的原因**：这几项的作用都是绕过平台的反作弊，或者批量处理他人的数据。
- 我们的用户是小白，账号最容易因此被限流、封号，等于卖给用户一个会害他封号的功能
- 批量采集评论会收集他人的个人信息，拿来商用售卖有法律风险（《个人信息保护法》）
- 规避平台检测的部分我不会帮忙实现

### 运营功能的技术方案

- 新建 Python 模块 `ops/`（我们自己的代码），通过一个小补丁挂到 Easel 后端，接口统一在 `/api/dazi/*` 下。和前端同源，不用多开一个进程
- 数据存在本地 SQLite（`<数据目录>/app/outputs/_dazi/ops.db`）
- 后台同步任务统一限速：同一账号的写操作（回复、发布）之间至少间隔 N 分钟，每天有上限；读操作低频执行

## 3. 视觉方向（已选 A）

同一份内容做成三种风格，效果图：`docs/design/方向*.png`，源文件：`docs/design/mocks/`。

### A · 暖橙手帐 —— "有个搭子陪着你做"
- **情绪**：亲切、轻松、不怕做错
- **视觉**：奶油纸色底，logo 的珊瑚橙作主色；按钮和输入框带**实心偏移阴影**（像贴纸），标签微微倾斜；标题下有手绘波浪线；logo 里的两个小幽灵用于空状态、加载、成功提示
- **适合**：新手，尤其是女性和生活方式类创作者（小红书主力人群）
- **风险**：做过头会显得幼稚；专业用户可能觉得不够"工具感"
- **不要做**：满屏插画、每个角落都放吉祥物、彩虹配色

### B · 创作者工作室 —— "我在用专业工具做内容"
- **情绪**：专注、高效、有成就感
- **视觉**：深色界面（也提供浅色），**作品缩略图占主角**，界面本身尽量不抢眼（参考剪映、Figma）；窄图标栏 + 右侧"进行中 / 本周发布"面板；橙色只用于主要操作
- **适合**：有一定经验、产出量大、做视频较多的创作者
- **风险**：新用户还没有作品时，页面会显得空；深色对小白不够亲切
- **不要做**：霓虹光效、玻璃拟态、渐变光斑

### C · 杂志编辑部 —— "每天一场选题会"
- **情绪**：有品位、有条理、像有个主编在帮你
- **视觉**：首页做成报纸头版：「今日选题会 · 第 12 期」，宋体大标题，细线分栏；头条选题附带理由（热度数据 + 和账号的匹配度）；橙色只作点缀
- **适合**：图文、知识类、公众号创作者
- **风险**：中文宋体需要随软件带字体文件（思源宋体子集约 3–5MB）；年轻用户可能觉得严肃；信息密度高
- **不要做**：做成真的报纸（假折痕、泛黄纸）

### 我的建议：**A 为主，吸收 B 的"作品预览优先"**
- A 和 logo 的气质一致，最贴合"小白 + 搭子"的产品定位，而且去掉 logo 也认得出来
- 「创作」页和「我的作品」借用 B 的做法，让生成的卡片和视频成为画面主角。用户花钱买的是作品，作品应该最显眼
- C 的"每个选题附带推荐理由"值得保留，放进 A 的选题卡片里（效果图 A 已经带上了）

## 附：U1 设计系统说明

- **文件**：`frontend/src/styles/tokens.css`（token）、`styles/ui.css`（组件样式，`dz-` 前缀）、`src/ui/index.tsx`（React 组件）、`src/lib/theme.ts`（主题）
- **两个橙色**：logo 色 `#EF5A3A` 上放白字，对比度只有 3.39:1，达不到 4.5:1 的标准。所以按钮和角标这类白字底色用 `#D4401F`（4.61:1），logo 色只用于装饰
- **对比度**：所有正文文字色在浅色和深色下都 ≥ 4.5:1；`--dz-ink-3`（3.7:1）只用于占位符
- **旧页面过渡**：`tokens.css` 末尾把旧变量名（`--text`、`--border`、`--accent-*` 等）映射到新 token，所以旧页面已经换上了暖色。某个页面重写完就不再依赖这段映射，全部重写后删掉
- **深色模式暂不开放**：旧页面的样式里有写死的浅色，跟随系统深色会出现一半深一半浅的效果。深色模式先只在展示页生效（`DARK_READY`，在 `index.html` 和 `theme.ts` 两处），页面全部重写后再打开

## 附：U3 说明

- **三栏**：历史栏 + 对话 + 右侧「这次的作品」。作品栏在生成过程中每 5 秒刷新一次，做好的卡片、图片、视频直接出现；点缩略图看大图，左右键翻页，HTML 排版在沙箱里预览（脚本能跑，碰不到本软件）
- **怎么认出"这次的作品"**：① 回复里提到的 `outputs/<作品>`；② 每一轮生成的起止时间（存在会话的 `turns` 里）内有文件改动的作品。第 ② 条让用户中途切走、再回来也不会漏；两个对话同时生成时，可能互相认领对方的作品，影响不大
- **窗口宽度**：≥1200 三栏并排；更窄时作品栏浮在对话上面，默认收起，点右上角「这次的作品」展开
- **新对话**：吉祥物 + 大输入框 + 6 个模板（`lib/templates.ts`，「今天」页共用）。模板只填进输入框，不直接发送；新对话还没开始时不显示作品栏
- **全部能力**：114 个技能按 10 个场景分组（`SCENARIO_OF`，没列到的新技能按上游分层兜底），可搜索、可筛选。不再显示技能 ID、「需 API」和密钥配置。点一项会开新对话，输入框里预填「用「X」帮我做：」，发送时额外告诉搭子用哪个技能（界面上不显示）
- **出错提示**：对话报错改成大白话（额度用完、验证失败、太频繁、网络），原始报错收在「详情」里
- 新建对话时顺手清掉没用过的空对话，历史栏不再堆一串「新的创作」
- 删除了上游的 `SkillPage` / `SkillDrawer`（技能库和密钥配置抽屉）；`index.css` 里对应的旧样式留到 U5 一起清理
